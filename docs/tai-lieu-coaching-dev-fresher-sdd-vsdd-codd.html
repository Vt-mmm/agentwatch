Từ Vibe Coding đến Spec-Driven Development

Tài liệu học nhanh, áp dụng ngay vào task thật: giúp Dev Fresher biết cách dùng AI để code có kiểm soát, tránh “phê lúc đầu, vỡ hệ thống lúc sau”, và nâng cấp vai trò từ người nhờ AI viết code thành người điều khiển ý đồ kỹ thuật.

1. Mục tiêu buổi coaching

Nhận diện vấn đề

Dev hiểu vì sao Vibe Coding chạy rất nhanh ở demo nhưng dễ sụp khi dự án có nhiều module, nhiều người, nhiều trạng thái.

Có quy trình thay thế

Dev biết chuyển từ prompt mơ hồ sang bộ Spec tối thiểu trước khi yêu cầu AI viết code.

Áp dụng vào task ngay

Mỗi task phải có Spec, test case, checklist kiểm chứng và ghi nhận ràng buộc trước khi merge.

AI có thể viết code rất nhanh. Nhưng người kỹ sư vẫn phải định nghĩa đúng ý đồ, ràng buộc và tiêu chí hoàn thành.

2. Vấn đề cốt lõi: Vibe Coding không giữ được “ý đồ thiết kế”

Vibe Coding là cách dùng AI theo cảm hứng: mô tả nhanh, yêu cầu AI viết code, chạy thử, rồi sửa tiếp. Cách này tạo cảm giác rất hiệu quả ở giai đoạn đầu vì có sản phẩm chạy được chỉ sau vài phút.

Nhưng khi dự án lớn hơn, AI bắt đầu mất bối cảnh. Nó không tự nhớ được toàn bộ quyết định kỹ thuật, rule nghiệp vụ, trạng thái dữ liệu, edge case và các phần không được phá vỡ.

Dấu hiệu Biểu hiện trong task thật Hậu quả
Context sụp đổ AI quên logic cũ, viết code mới không khớp module hiện tại. Code chạy được ở một case nhưng lệch kiến trúc tổng thể.
Bug dây chuyền Sửa màn hình này thì vỡ API kia; sửa role Shop thì hỏng role User/Admin. Dev mất nhiều giờ debug hậu quả do AI sinh ra.
Kỹ sư kiệt quệ Thời gian đọc lại, sửa lại, hỏi lại AI nhiều hơn thời gian tự thiết kế. Team tưởng nhanh nhưng velocity thật bị giảm.
Luật cảnh báo: Nếu dev không thể giải thích task bằng flow, rule, input/output và test case trước khi prompt AI, thì dev chưa sẵn sàng để cho AI viết code.

4. Mô hình 3 tầng: SDD → VSDD → CoDD

Tầng 1

SDD

Spec-Driven Development

Viết Spec tối thiểu để AI không đoán mò. Spec là bộ nhớ ngoài của task.

Tầng 2

VSDD

Verified Spec-Driven Development

Kiểm chứng code có đúng với Spec, ý đồ và edge case không.

Tầng 3

CoDD

Coherence-Driven Development

Giữ tính nhất quán toàn hệ thống khi nhiều module phụ thuộc nhau.

Cách hiểu đơn giản cho Fresher

Tầng Câu hỏi chính Sản phẩm đầu ra
SDD Mình muốn AI làm chính xác cái gì? Spec task rõ ràng
VSDD Code AI viết đã đúng ý đồ chưa? Checklist verify + test case
CoDD Sửa task này có làm lệch hệ thống không? Dependency map + constrained_by

5. Quy trình Step by Step áp dụng vào mọi task

1

Đọc task và viết lại bằng ngôn ngữ của mình

Dev phải tự diễn giải lại task trước khi dùng AI. Nếu không diễn giải được, nghĩa là chưa hiểu task.

Task gốc:
Shop upload ảnh hóa đơn để đối chiếu eVoucher.

Dev viết lại:
Khi Shop upload ảnh hóa đơn, hệ thống lưu ảnh, tạo record invoice_verification,
gắn với eVoucher đã scan, trạng thái ban đầu là pending_review, sau đó chuyển qua approved/rejected.
2

Xác định user role và quyền

Không có role rõ ràng thì AI rất dễ viết API/màn hình sai quyền.

Role liên quan:
- Shop: upload hóa đơn, xem trạng thái đối chiếu.
- User: xem giao dịch eVoucher của mình.
- Admin: duyệt hoặc từ chối hóa đơn.
Không cho Shop duyệt hóa đơn của chính mình.
3

Viết input/output

AI cần biết dữ liệu vào, dữ liệu ra và format lỗi.

Input:
- voucher_id
- shop_id
- invoice_image
- invoice_amount
- note optional

Output success:
- verification_id
- status: pending_review
- image_url
- created_at

Output error:
- voucher_invalid
- voucher_expired
- file_too_large
- permission_denied
4

Vẽ flow xử lý

Flow giúp dev và AI không nhảy cóc logic.

Flow:
1. Shop scan eVoucher.
2. System kiểm tra voucher active.
3. Shop upload ảnh hóa đơn.
4. System validate file.
5. System tạo invoice_verification.
6. Admin review.
7. Nếu approved: ghi nhận sử dụng eVoucher.
8. Nếu rejected: giữ voucher ở trạng thái cũ và ghi lý do.
5

Liệt kê edge case

Edge case là nơi AI thường bỏ sót nhất.

Edge case:
- Voucher đã expired.
- Voucher đã used.
- Shop upload ảnh trùng.
- Ảnh quá dung lượng.
- User không thuộc voucher.
- Admin reject nhưng thiếu lý do.
- Mạng lỗi sau khi upload ảnh nhưng trước khi tạo record.
6

Viết prompt cho AI dựa trên Spec

Không prompt kiểu “làm tính năng upload hóa đơn”. Prompt phải ép AI bám Spec.

Prompt chuẩn:
Bạn là senior backend engineer. Hãy triển khai API upload invoice cho Shop theo Spec dưới đây.
Không tự ý đổi schema. Không thay đổi logic voucher hiện tại.
Trước khi code, hãy liệt kê các file cần sửa và rủi ro ảnh hưởng.
Sau khi code, hãy tạo test case cho success, permission_denied, voucher_expired, file_too_large.

[PASTE SPEC HERE]
7

Kiểm chứng bằng VSDD trước khi merge

Sau khi AI viết code, dev phải kiểm tra code có đúng Spec không, không chỉ kiểm tra “có chạy không”.

Checklist VSDD:
- Code có đúng role không?
- Code có đúng trạng thái không?
- Có phá flow cũ không?
- Có test case cho edge case không?
- Có log/audit cho hành động quan trọng không?
- Có lỗi nào bị AI tự giả định không?

7. VSDD: Vòng kiểm chứng code AI

Với Dev Fresher, lỗi phổ biến là thấy AI code chạy được thì nghĩ đã xong. Nhưng trong sản phẩm thật, “chạy được” chưa đủ. Code phải đúng Spec, đúng ý đồ và không làm lệch hệ thống.

Bước kiểm chứng Câu hỏi dev phải trả lời Kết quả mong muốn
Spec Match Code có bám đúng từng mục trong Spec không? Không có logic tự ý thêm/sửa ngoài yêu cầu.
Role Check Quyền User/Shop/Admin có đúng không? Không lộ quyền, không bypass permission.
State Check Trạng thái dữ liệu có chuyển đúng không? Không có trạng thái mồ côi hoặc trạng thái sai.
Regression Check Có làm hỏng tính năng cũ không? Test cũ vẫn pass.
Edge Case Check Các case xấu đã được xử lý chưa? Lỗi trả về rõ, không crash, không mất dữ liệu.
Audit Check Hành động quan trọng có log không? Có thể truy vết người làm, thời điểm, dữ liệu thay đổi.
Khẩu quyết VSDD: Không hỏi “AI code xong chưa?”. Hãy hỏi “Code này đã chứng minh được là đúng với Spec chưa?”.

8. CoDD: Giữ tính nhất quán khi task chạm nhiều module

CoDD dành cho task có ảnh hưởng dây chuyền. Fresher chưa cần làm phức tạp, nhưng phải biết khai báo phụ thuộc bằng constrained_by. 

Ví dụ constrained_by cho task eVoucher:

constrained_by:
- Voucher chỉ được redeem nếu status = active.
- Shop chỉ được upload invoice sau khi scan voucher hợp lệ.
- Một voucher chỉ được approved một lần.
- Admin phải ghi reason khi rejected.
- Mọi thay đổi status phải ghi audit log.
- Không update đè lịch sử giao dịch.

9. Bài tập thực hành ngay trong buổi coaching

Bài tập 1: Chuyển prompt mơ hồ thành Spec

Prompt mơ hồ: “Làm chức năng Shop upload hóa đơn để trừ eVoucher.”

Yêu cầu: Dev viết lại thành Minimum Spec Set gồm mục tiêu, role, input/output, flow, edge case, DoD.

Bài tập 2: Bắt lỗi Spec thiếu

Lead đưa một Spec cố tình thiếu edge case. Dev phải tìm ít nhất 5 điểm mơ hồ trước khi cho AI code.

Bài tập 3: Viết prompt AI chuẩn

Dev dùng Spec đã hoàn thiện để viết prompt yêu cầu AI: phân tích file cần sửa, rủi ro, code, test case.

Bài tập 4: VSDD Review

Dev nhận code AI sinh ra và đối chiếu từng dòng logic với Spec. Mục tiêu: tìm điểm AI tự ý giả định.

10. SOP giao task cho Dev Fresher dùng AI

Giai đoạn Dev phải làm Lead/CTO kiểm tra
Trước khi code Viết Minimum Spec Set, edge case, constrained_by. Spec có đủ rõ để AI không đoán mò không?
Khi prompt AI Yêu cầu AI phân tích trước khi code, không cho sửa lan man. Prompt có giới hạn phạm vi không?
Sau khi AI code Đọc diff, kiểm chứng với Spec, chạy test. Dev có hiểu code hay chỉ copy?
Trước khi merge Nộp VSDD checklist và test result. Không có bug dây chuyền, không phá rule cũ.
Sau khi merge Ghi lại lesson learned và điểm AI đã sai. Cập nhật Spec/knowledge base nếu cần.

11. Bảng đánh giá Fresher sau buổi coaching

Năng lực Mức chưa đạt Mức đạt Mức tốt
Hiểu task Copy yêu cầu, chưa diễn giải được. Diễn giải được mục tiêu và flow chính. Phát hiện được điểm mơ hồ, rủi ro, edge case.
Viết Spec Spec thiếu role, input/output, DoD. Có Minimum Spec Set đầy đủ. Spec rõ tới mức AI có thể code ít sai.
Dùng AI Prompt ngắn, mơ hồ, phụ thuộc AI đoán. Prompt theo Spec, có giới hạn phạm vi. Biết yêu cầu AI phân tích rủi ro trước khi code.
Verify code Chỉ chạy thử UI/API đơn giản. Đối chiếu code với Spec và test case. Phát hiện hallucination, regression, sai state.
Tư duy hệ thống Chỉ nhìn file mình sửa. Biết module liên quan. Biết khai báo constrained_by và downstream impact.
Tiêu chuẩn qua buổi: Dev có thể nhận một task thật, viết Spec tối thiểu trong 15–30 phút, prompt AI đúng cấu trúc, và tự kiểm chứng code trước khi nhờ Lead review.

15. Kết luận cho buổi coaching

Vibe Coding không sai. Nó rất tốt cho demo, prototype và khám phá ý tưởng. Nhưng khi bước vào sản phẩm thật, nhất là hệ thống có dữ liệu, tiền, phân quyền, workflow và audit log, team phải chuyển sang SDD/VSDD/CoDD.

Dev Fresher muốn dùng AI hiệu quả không phải là người gõ prompt nhiều nhất, mà là người biết biến yêu cầu mơ hồ thành Spec rõ, biết kiểm chứng code AI và biết giữ tính nhất quán của hệ thống.
